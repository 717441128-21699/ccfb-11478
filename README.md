# 统计数据差分隐私发布工具

统计部门对外发布分区县人口/收入交叉表的浏览器端工具。原始数据只在本机内存中处理,
无任何网络上传;加噪、预算扣减、一致性后处理、小格子抑制、审计全部在本地完成。

## 快速开始

```bash
npm install
npm run gen       # 生成 50 万人合成人口 → data/population.csv
npm run verify    # 运行精度 + 攻击验证套件(见下)
npm run serve     # 启动本机服务 → http://localhost:8080/
```

打开页面后按页签操作:

1. **原始数据** — 导入 CSV,或一键生成内置合成人口(50 万)。字段自动识别为
   分类(维度)/数值(指标),可手工改。
2. **表格设计** — 选 1–3 个交叉维度、指标(计数/合计/均值)、机制(拉普拉斯/高斯)、
   本表 ε、抑制阈值,加入发布计划;计划列表中可逐表调 ε。
3. **隐私预算** — 设总预算 ε/δ,查看已消耗/计划占用/剩余;计划超额会警告。
4. **发布预览** — 发布前按格子大小分桶给出相对误差的解析分布(不耗预算);
   点「发布」一次性加噪、扣预算、写审计,可下载发布 CSV。
5. **审计记录** — 谁、何时、发了什么表、用了多少预算,localStorage 持久化,可导出 JSON。

## 隐私设计

- **隐私单元**:个人(每人一行)。计数敏感度 Δ=1;求和按截断上界 B 裁剪,Δ=B;
  均值不单独发布,由加噪的合计/计数派生。
- **机制**:拉普拉斯(纯 ε-DP,b=Δ/ε);高斯((ε,δ)-DP,σ=Δ·√(2ln(1.25/δ))/ε)。
  表内多个原子查询均分该表预算。
- **组合**:基本组合,总 ε、δ 为各次发布之和;预算耗尽即拒绝发布。
  每次发布(含重复发布同一表)都重新加噪并计费——这是抵御"两版相减"攻击的关键。
- **一致性后处理**:加噪 → 非负截断 → 最大余数法保总取整;边际合计一律由
  取整后的格子求和派生,因此"子项加总 = 合计"在表内恒成立。
- **小格子抑制**:加噪计数 < 阈值的格子主抑制;再做配合抑制,保证每行/列被抑制
  格子数为 0 或 ≥2,使"边际减格子"的方程组欠定,无法反解被抑制值;
  发布的合计只含已发布格子,进一步切断反推路径。
- **加噪随机源**:正式发布用 `crypto.getRandomValues`;合成数据与验证脚本用种子 PRNG
  以便复现。

## 验证(`npm run verify`,结果见 verify-output.txt)

在 50 万合成人口上发布 5 张表(拉普拉斯 + 高斯),自动检查:

| 检查 | 结果 |
|---|---|
| 大格子(≥500 人)计数相对误差 P95 ≤ 5% | 实际 P95 ≤ 0.65% |
| 大额收入合计(≥2 亿)相对误差 P95 ≤ 5% | 实际 P95 ≤ 1.8% |
| 非负、整数、子项加总=合计 | 通过 |
| 预算耗尽拒绝发布 | 通过 |
| 差分攻击(两版相减推个人收入) | 无噪声时精确反推(误差 0%);加噪后误差中位 130%,误差≤10% 的比例仅 4.5% |
| 成员推断(判断某人是否在库) | 无噪声时 100%;加噪后 61.4% ≤ ε=0.5 理论上限 62.3% |
| 减法反解被抑制格子 | 每行/列抑制数为 0 或 ≥2,方程欠定;合计不含被抑制格 |

## 目录结构

```
src/core/      机制、预算账户、交叉表、后处理、抑制、误差模型、审计(纯 TS,无依赖)
src/synth/     合成人口生成器(种子可复现)
src/ui/        浏览器界面(原生 TS + DOM,无框架)
scripts/       gen-population(造数)、verify-dp(验证)、serve.js(本机服务)
data/          生成的 population.csv(约 14 MB)
```

## 已知边界

- 一致性保证在**单表内**成立;跨表共享边际(如两张表的区县合计)不做强制对齐。
- 组合会计采用基本组合(简单保守);如需发布几十张以上的表,可换 RDP 组合以省预算。
- 假设每人一行;若一人多行(如家庭户),需先按隐私单元聚合再导入。
