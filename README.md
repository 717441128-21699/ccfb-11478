# 区县人口收入交叉表 · 差分隐私发布工具

统计部门对外发布分区县人口/收入交叉表的浏览器端工具。**所有原始微数据只在本机浏览器内存中处理，不上传、不落盘，刷新页面即销毁。**

## 隐私模型与防护链条

| 环节 | 手段 | 保证 |
| --- | --- | --- |
| 加噪 | 拉普拉斯机制 `(ε,0)-DP`、高斯机制 `(ε,δ)-DP`（经典校准，要求单查询 ε<1） | 每条输出都有严格 DP 语义，噪声尺度随预算实时显示 |
| 预算 | 串行组合记账，表级 ε 在基础指标间均分；多表 ε、δ 直接累加 | 总预算用完后发布请求被管线强制拒绝（`BudgetExhaustedError`） |
| 抑制 | 真实计数 < 阈值的格子 + 空格子进入抑制集；不足 k=3 格时按最小计数互补抑制 | 被抑制格子只以**一个加噪汇总桶**发布，减法只能得到桶总量，无法拆出任何单格（含 singleton） |
| 一致性后处理 | 非负裁剪 + 最大余数法整数化；合计恒等于各发布格子求和；人均收入由后处理值派生 | 无负数、无非整数、子项加总严格等于合计；后处理不消耗额外预算（DP post-processing） |
| 审计 | 每次发布自动记录操作员/时间/表设计/预算消耗/误差/抑制数，持久化 localStorage，可导出 CSV | 可追溯"谁发了什么、用了多少预算"，审计中不含任何真实格子值或个人记录 |

## 功能模块（界面五步）

1. **原始数据**：CSV 拖拽导入（必需列 `id,district,ageGroup,gender,education,occupation,householdSize,income`），或一键生成 5 万/20 万/50 万合成人口；含维度分布画像与样例预览。
2. **表格设计**：1~4 个行维度、计数/收入总额/人均收入指标可选；机制、ε、δ、抑制阈值、收入裁剪上界可调；实时估算噪声尺度与真实网格规模。
3. **隐私预算**：ε/δ 双账本、逐次消耗明细、剩余额度、耗尽拦截、总预算重置。
4. **发布预览**：执行加噪发布，展示相对误差分布（均值/中位/P90/最大，按真实计数 ≥1000 的大格子单列），渲染带抑制桶与合计行的交叉表，一键导出**只含发布值**的 CSV。
5. **审计记录**：全量发布留痕，支持操作员身份设置与审计 CSV 导出。

## 目录结构

```
src/
  lib/            与 DOM 无关的纯 TS 核心（浏览器与 Node 脚本共用同一条代码路径）
    types.ts        类型定义
    rng.ts          mulberry32 确定性随机数 + Laplace/Gaussian 采样
    mechanisms.ts   Laplace/Gaussian 校准、噪声采样、预算账本
    aggregation.ts  全维度笛卡尔网格聚合
    suppression.ts  主抑制 + 全局互补抑制（防减法反推）
    postprocess.ts  非负化 + 最大余数整数化（合计守恒）
    errors.ts       相对误差分布统计
    pipeline.ts     发布管线（预算校验→聚合→抑制→加噪→后处理→审计）
    synthetic.ts    带维度相关性的合成人口生成器
    csv.ts          CSV 解析 / 发布表 CSV 序列化
    storage.ts      预算与审计的 localStorage 持久化
    dimensions.ts   维度/指标字典
  components/     React 界面（五个标签页）
scripts/
  generate-data.ts  生成 50 万合成人口 CSV
  attack.ts         差分攻击验证（减法反推/成员推断/唯一性/预算/精度）
  smoke.ts          管线不变量冒烟测试
```

## 使用方式

```bash
npm install
npm run dev          # 启动浏览器工具（http://localhost:5173）

npm run gen:data     # 生成 data/synthetic-population.csv（50 万人，约 17MB）
npm run attack       # 差分攻击端到端验证（9 项检查）
npm run smoke        # 19 项管线不变量检查
npm run build        # 类型检查 + 生产构建
```

## 攻击验证结论（50 万人口，4 张表耗尽 ε=4）

`npm run attack` 的实测结果：

- **减法/差分反推**：反推值与真实值中位相对误差 ≈100%，相关系数 ≈0.20，攻击无法还原任何个人；
- **成员推断**：LLR 检验 AUC 全部落在对应单查询 ε 的理论包络 `1 − 0.5·e^(−ε/2)` 的 95% 蒙特卡洛统计带内（高斯表与低 ε 表 AUC≈0.5，近乎随机猜测）；
- **抑制**：singleton 与稀有格子（真实计数 <5）全部抑制；100 人微型数据集专项自测验证互补抑制与汇总桶不可拆分；
- **预算**：第 5 张表在预算耗尽后被拒绝；
- **精度**：真实计数 ≥1000 的大格子，计数相对误差最大值 **1.2% < 5%**（最优表 0.06%）。

## 重要工程说明

- 高斯机制采用 Dwork & Roth (2014) Thm A.1 经典校准，界面限制单指标 ε<1；需要更紧的噪声可替换为 analytic Gaussian（`mechanisms.ts` 单点修改）。
- 记账采用保守的**串行组合**（而非按格子并行组合），多表发布的预算声明偏保守、不会低估隐私损失。
- 收入指标通过裁剪到 `[0, incomeClip]` 获得有限敏感度（默认 20 万元）。
- 审计存于浏览器本机，适合内部留痕；防篡改场景应把审计 CSV 定期归档到只追加日志系统。
- 全部数据为合成虚构数据，不对应任何真实个人。
